# ADR-0001: Record Architecture Decisions

## Context and Problem

We need to capture architectural and technical decisions made during the design of OSS-Maintainer-AI so future developers and open-source contributors understand the background of the repository's layout.

## Decision

We will use Architecture Decision Records (ADRs) formatted in Markdown. ADRs are numbered sequentially and named using kebab-case.

## Status

Accepted

## Consequences

Every significant architectural pivot or configuration stack choice (e.g. testing libraries, linters, package managers) must be documented in a new ADR in `docs/adr/`.
